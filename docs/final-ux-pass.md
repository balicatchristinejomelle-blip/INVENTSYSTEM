## Required 29-item report

1. **Pages audited:** Owner Dashboard/Plants/Records/Reports/UsersAccess; Accounting Dashboard/RawMaterials/RRRecords/BranchRequests/Transfers/Transactions/Reports; Marketing Dashboard/Customers/Orders/FinishedGoods/MOTracking/Reports; Management Dashboard/Operations/Employees/AuditLogs/Reports/Settings; Plant Manager Dashboard/ProductionOrders/PelletInventory/MaterialUsage/IncomingTransfers/MainPlantRequests/Attendance/ShiftTurnover/FinishedGoods/RejectedRecycling/Reports; Production Dashboard/ShiftAttendance/ProductionOrders/Pellets/FinishedPipes/BarcodeScanner/Recycling/ClockOut/ShiftTurnover/History; shared Login/Profile/NotificationsPage/GenericPage. Existing correct workflows were reused.
2. **Roles audited:** Owner/Super Admin, Accounting, Marketing, Management, Plant Manager and Production. Navigation/RBAC and the universal-search authorization index remain unchanged.
3. **Empty states:** Table bodies now use a shared accessible no-result fallback when their rendered row array is empty. RecordRows/RecordList have equivalent fallbacks. Existing more specific empty rows/cards remain, and stock-target lists suppress the generic fallback where a specific message already exists.
4. **Active filters:** Compact read-only chips expose product/specification, material/location, search and date filters, with scoped clearing actions. Finished Goods exposes additional list/purpose context where useful. Existing selection controls and predicates remain; chips are not duplicate inputs.
5. **View-state preservation:** Selected list searches, filters, tabs, page numbers and view modes use a per-employee/per-role/per-page `hpai:ui-view:v1:` session namespace. Shared page search, product filters and dates also restore. Details/reference dialogs open in place. Existing filter-change pagination resets are retained but no longer fire merely because a restored list mounts. Malformed/inaccessible storage falls back safely; Owner area/section restoration is constrained to valid tabs. No form, password, selected transaction, authorization or business record is persisted by this helper. This is per-tab session persistence, not cross-device persistence. Existing sort behavior is unchanged; no new sorting was invented.
6. **Current context:** Retained current PO/specification/material/remaining-quantity context on Production screens. Scanner now also shows current shift/operator near its operation heading. Storage confirmation explicitly shows Current Location and derived Storage Purpose.
7. **Clickable references:** SO/MO/PO/RR/MR, batch/origin group, physical Pipe/Bag IDs and current barcodes open read-only details when present in the existing authorized index. Unknown/unauthorized references remain text. Multiple matching physical records are shown as matches rather than arbitrarily choosing one. Shipment references are linkable only when actually recorded on authorized physical records; no shipment entity/reference is invented. If a permanent Pipe Record ID equals its former barcode, traceability explicitly warns that the old physical label is obsolete and displays the current barcode. Active barcode lookup/registry behavior is unchanged.
8. **Related Records:** Added compact, paginated authorized-reference sections to pipe/batch/receiving traceability and read-only reference details. Both outgoing and reverse relationships use actual recorded IDs/reference fields. Existing MO lifecycle/Linked Records and receiving bag details remain. Related lists and detail matches display at most 10 per page.
9. **Validation:** Preserved existing detailed production/quantity/Unit Weight/WIP/barcode/location messages and predicates. Added inline missing-Location feedback near receiving controls and accessible alert semantics. Unexpected UI callback exceptions use a sanitized message rather than exposing a stack trace. Real existing handlers were tested for missing Location, invalid quantity, missing Unit Weight, missing/insufficient WIP, duplicate scan and no active PO.
10. **Success messages:** RR, PO and Material Request creation notices observe actual newly saved records and use their existing references. Storage success includes the actual current barcode and confirmed Location. Existing Customer Order/MO, reservation, transfer, scanner receipt/load/release messages already carry transaction context and remain. No record is generated for a message, and a click alone is not reported as a successful save.
11. **Confirmations:** Added explicit final confirmations for receiving, finished-pipe receipt/release, physical storage/movement and crushing execution where needed. Existing approval, deactivation, reprint, turnover and crushing-approval dialogs remain. No confirmations were added to search, filters, record viewing, tabs or pagination. Invalid forms still reach their original validation rather than generating a transaction.
12. **Destructive-action safety:** Final Quality Reject uses the danger variant and a record-specific confirmation when its entered rejection data is present. Existing Reject/Deactivate/Reset/Reprint safety patterns remain. Danger/positive action pairs have a visible separation; original handlers and permissions remain.
13. **Help:** Small keyboard-reachable disclosures explain the five inventory metrics and selected pipe terminology (Origin Group, Storage Purpose, Pipe Record ID/current barcode/location, Material Grade). Help is opt-in, not a paragraph on every card.
14. **Status consistency:** Shared badges normalize clear display equivalents such as Ready for Release → Ready for Ship Out, Shipped Out → Shipped, Low/Out of Stock and Replenishment In Progress. Raw-material `Released` remains distinct: a consumed pellet bag must not be mislabeled as shipped. Stored enums, comparisons, transitions and filters are untouched.
15. **Location visibility:** Retained direct Location columns, receiving location, barcode-result location, material inventory locations and inventory movement history. New read-only reference details expose recorded current/receiving/storage locations. Storage/move confirmations state the actual selected destination.
16. **Scanner:** Replaced the no-op focus helper with a visible, keyboard-focusable hardware-capture area and scheduled focus recovery. Existing fast-keyboard/Enter capture and manual fallback remain; no camera dependency. Hardware capture is suspended while a modal is open, preventing a different scan from replacing a record behind a confirmation. Duplicate processing keeps the workflow open with explicit feedback; rapid duplicate input gets a non-mutating status message.
17. **Last Updated:** Inventory summaries, finished-goods availability and material inventory show a subtle last-recorded-update value from saved record timestamps. It is explicitly not a live-sync timestamp; no current time is invented when records have no timestamp.
18. **Dashboards:** Retained existing concise counts, exception notices, low-stock summaries and role-authorized shortcuts/drill-downs. Dashboard reference links are now actionable where authorized. No new full-module tables or duplicate primary workflows were added.
19. **Unsaved work:** Modal dismissal can protect supplied drafts, explicit restored-output dirtiness and nested storage edits. Covered forms include RR, transfer, customer/order, MR, replenishment, specification/target/location, production output, quality rejection and pellet/pipe storage movement. Cancel/Back buttons on editable modals use the same guard as overlay/Close/Escape. Browser unload warns only for actual dirty state. Existing production output/turnover draft storage remains unchanged. Leaving without saving calls the original dismissal callback; it does not silently clear existing retained form state.
20. **Duplicate submissions:** A synchronous ref-backed gate wraps mutating UI buttons for order/receiving/request/PO creation, reservation, storage, output, recycling, clock/turnover and applicable final actions. The first valid callback still runs immediately, once; repeated clicks are ignored while pending. Existing backend-independent store and reprint locks remain. Unit tests verify immediate double clicks, subsequent valid attempts and exception unlock.
21. **Loading states:** Guarded actions expose disabled/aria-busy state and brief Working feedback while pending. No artificial delay is inserted before the original first transaction callback. Print-session completion behavior remains owned by the existing print workflow.
22. **Read-only clarity:** Derived source/purpose, identity, assigned user/shift and record details remain non-editable. Read-only reference drawers contain no stock mutations. Existing read-only inputs retain readable theme colors instead of faded disabled styling.
23. **Filtered empty results:** No-result tables/cards explain that no matching records exist and suggest clearing or adjusting the visible filters. Existing screen-specific Clear Filters actions are retained; active chips add scoped clearing where appropriate.
24. **Pagination/counts:** The unchanged PAGE_SIZE/pageRecords function still limits lists to 10. Existing Showing X–Y of N feedback remains. Redundant Previous/Next controls are omitted for a single page; restored out-of-range pages normalize to the valid visible page. No new page-size setting or pagination algorithm was introduced.
25. **Mobile:** Existing mobile table/card behavior is retained. Added chips wrap/stack, reference values wrap, detail grids become one column, and existing action stacking/touch sizes remain. CSS checks cover 360/375/390/412/430 px. Actual viewport/overflow QA remains pending a connected browser.
26. **Accessibility:** Empty/success/error feedback has appropriate status/alert semantics; action locks expose disabled/busy state; reference/help controls are keyboard reachable. Shared modals add a top-dialog-only Tab boundary, Escape handling and focus restoration, including nested confirmations. Actual keyboard and physical-scanner interaction is unverified, not certified by SSR.
27. **Build:** `pnpm.cmd build` and `pnpm.cmd exec tsc --noEmit` pass. The existing nonblocking >500 kB bundle warning remains; no dependency/backend refactor was made.
28. **Dev server:** Reused the already running Vite server per AGENTS.md; localhost:8443 returns HTTP 200. No duplicate server was started and no browser data was reset.
